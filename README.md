# Telemedicine – Diabetes Monitoring System

A Python-based telemedicine application for the **remote monitoring and management of patients with Type 2 Diabetes**.

The system provides different interfaces and functionalities for **patients, diabetologists, and service administrators**, allowing users to manage therapies, record blood glucose measurements and medication intake, exchange messages, and receive automated reminders and alerts.

> **Academic project:** developed as part of a Software Engineering / Computer Science university project. This application is a **didactic prototype** and is not intended for real clinical use.

---

## Features

### 👤 Patient

Patients can:

* Log in using their personal credentials
* Record daily blood glucose measurements

  * Before meals
  * After meals
* Record medication and insulin intake
* View active and historical therapies
* View their blood glucose trends through charts and statistics
* Report symptoms, conditions, or concurrent therapies
* Receive reminders and alerts
* Communicate directly with their assigned doctor through the messaging system

The system can also use the collected information to monitor therapy adherence.

### 👨‍⚕️ Diabetologist

Doctors can:

* Log in to the system
* View their assigned patients
* Access patient clinical data
* Create, modify, and end therapies
* Monitor therapy adherence
* View blood glucose trends
* Receive alerts for abnormal measurements and missed medication
* View patient reports and statistics
* Update patient information
* Communicate with patients through the integrated messaging system

### 🧑‍💼 Service Secretary

The secretary is responsible for the administrative management of the system and can:

* Create new patient accounts
* Create new doctor accounts
* Assign doctors to patients
* Manage authentication credentials
* Verify user data

---

## Automated Monitoring

One of the main aspects of the application is the automated monitoring of patient data.

The system can:

* Check medication intake against the prescribed therapy
* Remind patients to record measurements and medication intake
* Generate alerts for abnormal blood glucose values
* Notify doctors when patients fail to follow their therapy for more than three consecutive days
* Generate alerts when patients record medications that differ from their prescribed therapy

### Blood Glucose Monitoring

Patients can record measurements both **before and after meals**.

The project defines the following reference thresholds:

| Measurement  | Reference range |
| ------------ | --------------: |
| Before meals |    80–130 mg/dL |
| After meals  |     < 180 mg/dL |

The doctor can then visualize the patient's measurements over weekly or monthly periods.

## Architecture

The application follows the **Model–View–Controller (MVC)** architectural pattern.

```text
                 ┌─────────────────────┐
                 │        View         │
                 │    Dash Interface   │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │     Controller      │
                 │ Application Logic   │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │       Model        │
                 │ Business + ORM     │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │      Database       │
                 │      PonyORM        │
                 └─────────────────────┘
```

The **Model** manages data and persistence, the **View** provides the user interface, and the **Controller** coordinates application events and business logic.

---

## Design Patterns

Several software design patterns were applied during development.

### Creational

* **Singleton** – used for the `OrmModel` instance and centralized database access.
* **Factory Method** – used to dynamically generate parametrized measurement callbacks.

### Structural

* **Facade** – `OrmModel` provides a high-level interface between controllers and the persistence layer.
* **Repository** – database access is centralized through specialized methods for the different application domains.

### Behavioral

* **Observer** – Dash callbacks react to events generated by the user interface.
* **Template Method** – controllers expose a common `register_callbacks(app)` interface.

## Installation

### 1. Clone the repository

```bash
git clone https://github.com/steperusi/diabetes_monitoring_app.git
cd diabetes_monitoring_app
```

### 2. Create a virtual environment

```bash
python -m venv venv
```

### 3. Activate the virtual environment

**Windows PowerShell:**

```powershell
.\venv\Scripts\activate
```

### 4. Install dependencies

```bash
pip install -r requirements.txt
```

### 5. Start the application

```bash
python app.py
```

These are the project's documented startup steps.
